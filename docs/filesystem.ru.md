# Файловая система (диск `sconcur_local` и фасад `File`)

Фича Files из SConcur, подключённая к Laravel в двух местах:

- драйвер диска `sconcur_local` — `Storage::disk(...)` на локальном каталоге;
- биндинг `files` — фасад `File`, включается флагом.

Файловая операция на фиче выполняется внутри расширения, пока вызвавшая корутина
приостановлена, поэтому остальные запросы воркера продолжаются, пока отвечает диск. Что
умеет сама фича — в документации библиотеки, `vendor/sconcur/sconcur/docs/files.ru.md`.

## Когда используется фича

Выигрыш там, где байты вообще не пересекают границу с PHP — копирование, хеш, загрузка,
сохранённая из временного файла, — и там, где медленный диск иначе держал бы весь воркер.
На маленьком файле с тёплым кэшем страниц нативный вызов быстрее, а вызову вне корутины
некому уступить поток. Поэтому оба места следуют одному правилу:

- внутри корутины перечисленные ниже операции идут в фичу;
- вне корутины (загрузка приложения, artisan, собственный процесс тестов) каждый вызов
  нативный;
- ошибка на фиче передаёт вызов нативной реализации, и та отвечает на неё так, как
  отвечала всегда: `false`, предупреждение, которое Laravel превращает в `ErrorException`,
  исключение Flysystem с нативным сообщением. Неудачная операция выполняется дважды; зато
  ни один вызывающий код не видит исключений `SConcur\Exceptions\Files\*`.

Две ошибки не передаются: `FileStoppedException` (корутину сворачивают) и
`FileTimeoutException` (дедлайн, который поставило приложение, см. `timeout_ms` ниже).

`tests/Feature/Filesystem/` прогоняет каждый покрытый вызов через нативную реализацию и
через пакетную на одном и том же дереве, внутри корутины и вне её, и требует того же
ответа, того же исключения и тех же файлов с теми же правами.

## Диск `sconcur_local`

```php
// config/filesystems.php
'disks' => [
    'uploads' => [
        'driver'     => 'sconcur_local',
        'root'       => storage_path('app/uploads'),
        'visibility' => 'private',
        'lock'       => 0,
        'throw'      => false,
        'timeout_ms' => 0,
    ],
],
```

Запись — это запись диска `local` (`root`, `visibility`, `permissions`,
`directory_visibility`, `links`, `lock`, `url`, `throw`, `report`) плюс `timeout_ms`,
дедлайн одного вызова; `0` — без дедлайна, как нативно. Сам диск — фреймворковый
`LocalFilesystemAdapter`, поэтому `path()`, `url()`, `putFile()` и остальное — те же, что у
диска `local`. Отличается только адаптер под ним:
`SConcur\Laravel\Filesystem\SconcurLocalFilesystemAdapter`.

| Операция | На фиче |
|---|---|
| `get`, `read` | `Files::read`, без лимита размера, как у `file_get_contents` |
| `put`, `writeStream` | только при `'lock' => 0`, см. ниже; поток локального файла, прочитанный с начала, копируется без перехода в PHP — именно это делает `putFile()` для загруженного файла |
| `copy` | `Files::copy`; visibility сохраняется так же, как у диска `local` |
| `move` | `Files::move` |
| `delete`, `deleteDirectory` | `Files::delete`, `Files::removeDirectory` |
| `exists`, `fileExists`, `directoryExists`, `size`, `lastModified`, `getVisibility` | один `Files::stat` |
| `checksum` | `Files::hashFile` для `md5`, `sha1`, `sha256`, `sha512`; любой другой алгоритм — нативно |

Нативно и на этом диске: `readStream` (его контракт — PHP-ресурс), листинги (`files`,
`allFiles`, `directories` — листинг фичи не несёт прав доступа, а каждой записи нужна её
visibility), `makeDirectory`, `setVisibility` и `mimeType`.

Диск `local` пишет с `LOCK_EX`, если `lock` не говорит иного, а фича блокировок не берёт.
Поэтому при блокировке по умолчанию `put` и `writeStream` остаются нативными и диск пишет
ровно как `local`; `'lock' => 0` переводит их на фичу — и снова ровно так, как пишет диск
`local` с `'lock' => 0`: на месте, без блокировки.

`writeStream` из чего-либо, кроме локального файла, прочитанного с начала (`php://temp`,
сокет, уже частично прочитанный поток), записывается кусками по мере чтения. Начав читать,
он уже не может передать вызов — поток нельзя прочитать дважды, — поэтому ошибка там —
собственный `UnableToWriteFile`.

При сборке диска отклоняются с `RuntimeException`, а не игнорируются:

| Ключ | Почему |
|---|---|
| `serve` | маршрут, раздающий диск, фреймворк регистрирует только для драйвера `local` |
| `read-only`, `prefix` | их адаптеры живут в необязательных пакетах Flysystem, которых этот пакет не требует |

## Фасад `File`

```dotenv
SCONCUR_FILESYSTEM_FILES=true
SCONCUR_FILESYSTEM_TIMEOUT_MS=0
```

По умолчанию выключено. Фреймворк резолвит `files` на каждом запросе — поиск шаблонов,
компилятор Blade, переводчик, — поэтому заменить его решает приложение. С включённым
флагом `files` — это `SConcur\Laravel\Filesystem\Filesystem`, подкласс фреймворкового, и
меняются только эти вызовы:

| Метод | На фиче |
|---|---|
| `File::copy` | `Files::copy` |
| `File::move` | `Files::move` |
| `File::hash` | `Files::hashFile` для `md5`, `sha1`, `sha256`, `sha512`; любой другой алгоритм — нативно |
| `File::replace` | `Files::writeAtomic`, с теми правами, что даёт нативный метод |

Путь с обёрткой потока (`s3://`, `phar://`) и копирование файла на самого себя остаются
нативными.

Нативно намеренно: вызовы метаданных (`exists`, `isFile`, `lastModified`, `size`), которые
фреймворк делает на каждом запросе и которые переход через границу только замедлил бы;
всё с блокировкой (`get`, `put`, `append` с `$lock`, `sharedGet`); `getRequire` и
`requireOnce`, которые являются `include`; `link`, `glob`, `isReadable`, `isWritable`;
листинги на Finder, чей контракт — `SplFileInfo` из Symfony; `hasSameHash`, который считает
`xxh128` — такого алгоритма у фичи нет.

Код, который сам создаёт `new Filesystem()`, а не резолвит `files`, получает класс
фреймворка, как и раньше.

## Ограничения

- Нет файловых блокировок: у фичи нет `flock`.
- Листинги диска остаются нативными.
- Диск `sconcur_local` не умеет `serve` и не принимает `read-only` и `prefix`.
- `timeout_ms` — дедлайн ожидания вызывающего, а не системного вызова: поток, уже
  находящийся внутри `read(2)`, остаётся там, пока ядро не вернёт управление.
