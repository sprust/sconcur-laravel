# Presence-каналы

Отдельный этап, потому что это единственная часть задачи с распределённым
состоянием.

## В чём сложность

`Echo.join('room.1').here(users)` требует, чтобы при подписке клиент получил
полный список участников канала. Соединения размазаны по воркерам пула
(`SO_REUSEPORT` раздаёт их ядром), и воркер знает только своих. Список из одного
воркера — неверный ответ, а не неполный.

## Решение

Раздельная ответственность: снимок берём из общего хранилища, изменения —
из шины.

- `PresenceRepositoryInterface` — `join(channel, socketId, memberData)`,
  `leave(channel, socketId)`, `members(channel)`.
- Реализация по умолчанию — `CachePresenceRepository` поверх `Illuminate\Cache`:
  ключ `ws:presence:{channel}`, значение — карта `socketId => memberData`,
  запись под `Cache::lock`, TTL на запись обновляется при каждом изменении.
- При подписке воркер пишет участника в хранилище, читает полный снимок и
  отдаёт его в `pusher_internal:subscription_succeeded`.
- Одновременно публикует в шину `pusher_internal:member_added`; остальные воркеры
  раскладывают событие своим подписчикам канала. Так же на выходе — `member_removed`.

Хранилище — источник правды для снимка, шина — для живых уведомлений. Кеш при
этом не обязан быть Redis: у `Cache::lock` есть реализации для нескольких
драйверов, а приложению, которому нужен presence на нескольких воркерах, всё
равно нужен общий кеш.

## Осиротевшие записи

Воркер, убитый `SIGKILL`, не успевает вычистить своих участников. Против этого:

- TTL на ключ канала, продлеваемый при любом изменении;
- запись `worker_id` рядом с участником и вычистка чужих записей при старте
  воркера с тем же `worker_id` (перезапущенный слот убирает за собой);
- периодическая сверка — задача для пула периодических задач, но уже на стороне
  приложения, не пакета.

## Ограниченный вариант

Если приложению хватает одного ws-воркера (`SCONCUR_WS_WORKER_COUNT=1`), общее
хранилище не нужно: реестр процесса и есть полный список. Это должно работать
без Redis и без настройки — `PresenceRepository` тогда `InMemoryPresenceRepository`,
выбор по `config('sconcur.ws.presence.store')`, значение по умолчанию `auto`:
`memory` при одном воркере, `cache` при нескольких. Ошибиться здесь молча нельзя,
поэтому при `memory` и `workerCount > 1` команда старта пишет предупреждение.
