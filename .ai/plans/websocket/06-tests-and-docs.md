# Тесты и документация

## Тесты

Разделение то же, что в пакете уже есть: быстрые модульные проверки на чистых
классах и интеграционные — против живых сервисов, поднятых `make up`.

### Без расширения и без сети

| Тест | Что проверяет |
|---|---|
| `tests/Feature/Ws/MessageCodecTest` | кодирование и разбор кадров, в том числе `data` как строки с JSON внутри |
| `tests/Feature/Ws/ChannelNameTest` | разбор префиксов, отказ на `private-encrypted-` |
| `tests/Feature/Ws/SignatureVerifierTest` | подпись сходится и не сходится; presence с `channel_data`; `hash_equals` |
| `tests/Feature/Ws/ConnectionRegistryTest` | подписка, отписка, исключение `socket` из `toOthers`, снятие с учёта при закрытии |
| `tests/Feature/Ws/SocketIdGeneratorTest` | формат `\d+\.\d+`, уникальность внутри процесса |
| `tests/Feature/Ws/BroadcasterTest` | `validAuthenticationResponse` совпадает с тем, что принимает `SignatureVerifier` |
| `tests/Feature/Config/MasterConfigTest` | группа `ws` попадает в конфиг мастера и уходит из него при `WORKER_COUNT=0` |
| `tests/Feature/Console/CommandsAreRegisteredTest` | новая команда зарегистрирована |

Последние два — дополнение существующих тестов, а не новые файлы.

Самый ценный из них — `BroadcasterTest`: он замыкает петлю «подписал в
http-воркере — проверил в ws-воркере», и именно её ломает любая правка формата
подписи.

### С расширением и брокером

| Тест | Что проверяет |
|---|---|
| `tests/Feature/Ws/AmqpBusTest` | publish в fanout доходит до подписчика; своя очередь у каждого подписчика |
| `tests/Feature/Ws/WsServerIntegrationTest` | поднять сервер, подключиться `SConcur\Features\WsClient`, пройти connect → subscribe → получить событие из шины |

Интеграционный тест поднимает сервер в отдельном процессе — так же, как это уже
делают тесты, которым нужен живой рантайм. Клиент библиотеки (`WsClient`) избавляет
от необходимости тащить в тесты браузер.

Чего тестами не проверить и что проверяется руками на демо-странице: реальный
`laravel-echo`. Совместимость протокола подтверждается живым клиентом на этапе 1,
и это записывается в `07-stages.md` как условие готовности.

## Документация

- `docs/websocket.ru.md` — новый файл: как устроен пул, протокол, авторизация,
  шина, presence, ограничения. Диаграммы — mermaid, по правилам `.ai/README.md`.
- `README.md` и `README.ru.md` — раздел «WebSocket» в обеих версиях, секция в
  секцию: установка, конфиг Echo, ENV, команда, ограничения. Пара двуязычная,
  править только вместе.
- `.ai/README.md` — упоминание четвёртой среды выполнения в описании проекта и
  `src/Ws/` в разделе про архитектуру.
- Ссылок на `.ai/plans/*` в `README*` и `docs/` не появляется — это правило
  репозитория.

Что обязано быть сказано в README прямым текстом, иначе это узнают на проде:

1. `master:reload` рвёт ws-соединения (для http-пула он незаметен).
2. Вещание не гарантирует доставку: отвалившийся воркер пропускает события.
3. Драйвер шины `local` не доставляет между процессами и годится только для тестов.
4. Presence на нескольких воркерах требует общего кеша.
5. Секции `ws` не появится в уже опубликованном `config/sconcur.php` — её надо
   добавить руками или перепубликовать конфиг.
