# Шаг 6. CI и документация

## 6.1 `.github/workflows/release.yml`

За основу — файл `slogger.laravel`: тесты на каждом PR в `master`, релиз по изменению
`version` в `composer.json`, неизменяемые теги. Он хорошо прокомментирован, комментарии
сохраняем.

Отличия:

- **Матрица.** У `slogger.laravel` это PHP 8.2–8.4 × Laravel 10/11/12. Здесь так не
  выйдет: `src/` использует синтаксис PHP 8.4 (`private const array`,
  `new HttpServerRunner(...)->run(...)`). Предлагаемая матрица — PHP `8.4` × Laravel
  `^11.0`, `^12.0`, плюс отдельная нога с точным полом (`11.0.*`) — тем же приёмом и
  с тем же комментарием, что в оригинале: каретка всегда резолвится в свежий релиз, и
  заявленный пол иначе не проверяется никогда.
- **Расширение.** Перед `composer update` шаг качает `sconcur.so` из релиза
  `sprust/sconcur` по версии, которую резолвил composer, и включает его через
  `php.ini`. Без этого ни PHPStan (если оставим подавления минимальными), ни
  интеграционные тесты не пройдут.
- **Сервисы.** `services:` с mysql 8.4 и rabbitmq 4.1 — интеграционным тестам нужны
  живые бэкенды. Переменные окружения совпадают с `phpunit.xml`.
- **`paths` в триггере `push`.** Список из `slogger.laravel` дополняем `demo/**` и
  `workbench/**`; комментарий про «пропущенный путь = нет релиза на реальном
  изменении» оставляем.

Уточнить перед реализацией: приведение `require.laravel/framework` в `composer.json` к
матрице (см. открытый вопрос в [00-overview.md](00-overview.md)) — иначе CI заявляет
одно, а composer другое.

## 6.2 Документация

### Что есть сейчас

- `README.md` — 45 KB, **на русском**.
- `docs/fiber-safe-laravel-bridge.ru.md`, `docs/sconcur-coroutine-context.ru.md`,
  `docs/task-pool.ru.md` — на русском, с суффиксом `.ru`.

### Что делаем в этом шаге обязательно

1. **Раздел про окружение в `README.md`.** Сейчас README описывает пакет как
   библиотеку внутри чужого приложения. После этого плана у репозитория есть своё
   окружение, и это надо описать: `make setup`, что поднимается, где демо, какие порты,
   как читать панель телеметрии, как гонять проверки. Один новый раздел «Разработка»
   между «Установка» и «Конфигурация (ENV)».
2. **`demo/README.md`** — коротко: что демонстрирует каждый эндпоинт и как это
   проверить руками. Без дублирования корневого README.
3. **Сверка README с кодом.** Правило документации из `.ai/README.md` требует
   проверять каждое техническое утверждение по коду. README писался, когда пакет жил
   внутри `slogger.back`; в нём есть отсылки к чужому репозиторию — например,
   «В этом репозитории она заведена как цель `make queues-declare`, которую вызывают
   `setup`, `workers-restart`, `deploy-prod` и `deploy-dev`» — целей `deploy-*` здесь
   не будет. Такие места правим по факту.

### Что выносим в отдельное решение

**Билингва.** У `sconcur-php`, `slogger.back` и `slogger.laravel` документация ведётся
парами `X.md` (английский) / `X.ru.md` (русский) со строкой-переключателем в первой
строке. Здесь всё русское, включая корневой README без суффикса.

Приведение к общему правилу означает:

- `README.md` → `README.ru.md`, новый английский `README.md` (перевод 45 KB);
- `docs/*.ru.md` → плюс английские пары (ещё ~3 файла);
- строка-переключатель в каждом файле, внутренние ссылки по языку файла.

Это самостоятельный объём работы, сравнимый с остальными шагами вместе взятыми, и он
никак не влияет на `make setup`. **Предлагаю вынести в отдельный план
`.ai/plans/docs-bilingual.md` и делать после того, как окружение заработает.**
Нужно подтверждение: делать сейчас, делать потом или не делать.

## 6.3 Финальная проверка всего плана

На чистом клоне:

```bash
git clone <repo> && cd sconcur-laravel
make setup
# → открывается http://localhost:48081, страница живая
curl -sS http://localhost:48081/api/health
curl -sS 'http://localhost:48081/api/concurrent?n=10&ms=200'   # elapsed_ms ≈ 200
curl -sS -X POST http://localhost:48081/api/jobs -d 'payload=hello'
curl -sS http://localhost:48081/api/jobs                        # джоба обработана
curl -sS http://localhost:48081/api/stats                       # панель отвечает
make check                                                     # cs-fixer + stan + tests
```

Если каждая строка отработала — задача, поставленная в
[00-overview.md](00-overview.md), выполнена.
